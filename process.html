Which cell-tracking model should a biologist trust?

How we designed a three-view dashboard that compares LAP, Trackastra and LineageMapper against expert ground truth: the sketches, what broke when we used the real data, how we changed the design to fit one screen, and what the finished dashboard shows.

Aditya Choudhury (data processing, View 1) · Akshay Mhetre (View 2) · Daniel Shull (View 3)

1Use case and data

Use Case 2: choose a model for a new experiment.

Our users are biologists who are about to track cells in a new experiment and have to pick one of three tracking models. They need to know which model to trust for their cell line, and what kind of mistakes it will make. The brief lists four tasks, and each view answers at least one:

Locate disagreements and inspect the affected tracksView 3, individual links in image coordinates
12sequences with predictions (3 per cell line) out of 25 annotated

106,226true links, 567 divisions
293,657predicted links from 3 models
330,284labelled links in the dashboard

How a link is judged

A ground-truth link joins a cell to each ID in its CHILD_IDS, so a dividing cell has two links. A predicted link is source_cell_id → target_spot_id. We match every predicted link by ID: it is correct if the ground truth has the same link and wrong target otherwise. Every true link the model did not predict is missed. This gives 282,051 correct, 11,606 wrong-target and 36,627 missed links. We use every link of every predicted sequence, with no sampling.

Why F1 and not "accuracy". In Milestone 1 we defined accuracy as the share of predicted links that are correct (precision). On the real data that made LAP look close to perfect (0.99), because precision ignores the 7,103 links LAP never made. F1 combines precision with recall (the share of true links found), so a model that skips hard cases is no longer rewarded.

A Python script (prep/build_data.py) reads the raw zips and writes a summary table plus one small file per sequence × model. Each file is 0.14–0.71 MB, so View 3 loads one file per click instead of the 26.5 MB file of every link. Before writing anything, the script checks its results against the numbers in our Milestone 2 report, including all 36 heatmap values.

2Milestone 1: sketches and alternatives

Placeholder data, models still called A, B and C.

From the start we planned three views on one screen, read left to right in the order of Shneiderman's mantra: an overview by cell line, a sequence × model grid to zoom and filter, and a detail view of individual links. A model selector and one fixed hue per model (blue, green, pink) were meant to tie the views together. Both choices survived to the end.

View 1 · Grouped bars of accuracy

Designed by Aditya Choudhury

We chose bars because length on a common scale is the most accurate channel for comparing values, and grouping by cell line answers "which model is best here?" directly. We sketched the same placeholder values three other ways and dropped them all. A table makes you compare 12 numbers one by one. A line chart implies an order between cell lines that does not exist. A radar chart relies on radial lengths and areas that are hard to judge.

View 2 · Sequence × model heatmap

Designed by Akshay Mhetre

The heatmap gives every sequence × model pair its own large cell. A cell is easy to read and easy to click, so it can drive View 3. Colour lightness shows the score, and the hues stay on the column headers only, so a blue cell is never mistaken for "LAP". The dot plot was the strong runner-up. We dropped it because dots overlap when models score alike, and there is no single target to click for a pair. Parallel coordinates tangle with 12 lines and give lines a slope between unordered models.

View 3 · Trajectory plot of wrong links

Designed by Daniel Shull

The detail view draws cells at their pixel positions and the model's links between frames, so a biologist can see where a model goes wrong. For example, a wrong link might jump to a neighbouring cell while the true link goes elsewhere. Hovering a wrong link gives the frame, the source, the predicted target and the true target.

3Milestone 2: what broke with real data

Each view rebuilt in Python from all 330,284 links. We kept the failed versions on purpose.

Real data changed the design more than any sketch review. The scores fell in a narrow band (F1 0.78–0.98), the main difference between models turned out to be missed links rather than wrong ones, and a single sequence holds thousands of errors. Every view had to change.

The Milestone 2 dashboard

We put the three Python figures together into one dashboard image. View 1 sits across the top, with View 2 and View 3 below it. It worked as a figure, but it was taller than a screen. Two parts of its interaction plan were also progressive:

  • View 3 would start empty, with the message "Select a sequence in View 2".
  • Clicking a cell line would filter View 2 down to that cell line's rows.

The instructor's feedback pointed at exactly these two problems.

4Feedback and the one-screen redesign

"The final dashboard must have all figures visualized on the screen at the same time (no progressive views). Simplify so everything shows on screen at once. You can still have a progressive type of interaction, but don't design assuming a view will change completely from one mode to another." Dr. Iuricich, feedback on Milestone 2

We turned the feedback into three rules for the D3 version and checked every design decision against them:

  • Everything fits one screen at 1440×900 with no scrolling, and still looks right at 1920×1080. Text stays at 11 px or larger.
  • No view is ever empty.
  • Interactions highlight or update, and never hide a view or change it into a different kind of view.

View 3 opens on the weakest cell in the heatmap. Instead of an empty panel, the dashboard loads U87 · FLD_2 · LineageMapper (F1 0.78) at transitions 35–38. The first screen already tells the whole story from overview to detail, and its orange outline in View 2 shows where the detail comes from.

Clicking a cell line outlines it rather than filtering. The other nine heatmap rows stay at full strength, so comparing U87 with MCF10A is still one glance.

Choosing a model fades the others and updates View 3 in place. View 3 keeps its sequence and window and redraws with the new model's links. Links that both models share stay where they are, so the differences are what changes.

Every view was shrunk without dropping content.

  • View 1's two panels are stacked in a narrow column.
  • The heatmap's cell-line names became group headings, which frees enough width for three model columns.
  • View 3's summary box became a one-line strip that also works as its legend.
  • The link plot is sized to the image's aspect ratio, and the timeline gets the leftover height.

5Building it in D3

The site is plain HTML, CSS and JavaScript with D3 v7 and no build step, so it runs on GitHub Pages as is. There is one file per view, plus main.js, which holds the one shared state object: selected model, outlined cell line, sequence and model shown in View 3, window start, and hovered cell.

  • Each view has a draw step and an update step. draw() lays the view out from its box size. update() applies the state with 300 ms transitions. A ResizeObserver redraws when any box changes size.
  • View 3 fetches only what it shows. It loads one sequence × model file per click and caches it, so revisiting a cell is instant.
  • All layout decisions were tested with screenshots. A headless browser took screenshots at 1440×900, 1920×1080 and 1366×768 after every stage and checked the console for errors. The screenshots caught problems we would have missed by reading code:
    • the heatmap's colour chips sat under the subtitle instead of on the column headers
    • the legend's end labels were clipped
    • the timeline was sized before the summary text arrived, so the page ended up 4 px taller than the screen

6What the dashboard reveals

LAP is the safe choice everywhere

LAP has the best F1 in every cell line, and its F1 stays between 0.94 and 0.98 on all 12 sequences (pooled 0.96). Its precision is 0.99: when LAP makes a link, it is almost always right.

For the other two models, the cell line matters more than the model

Trackastra and LineageMapper score 0.95–0.97 on MCF10A and MDA-MB-231 but drop to 0.78–0.88 on HEK293T and U87. All three U87 sequences are dark for both models in the heatmap, so this is a property of the cell line, not of one bad sequence. Sequence size does not explain it: U87 FLD_4 has only 4,820 true links and is weak, while MDA-MB-231 FLD_2 has 13,992 and is strong.

LAP and LineageMapper mostly miss links, and LineageMapper misses the most. Trackastra makes the most wrong links, partly because it proposes 2,235 cell divisions and none of them is real. A wrong link is worse for a biologist than a missed one, because it silently joins two different cells into one track.

No model links a single cell division

All 1,134 division links (567 divisions × two daughters) are missed by all three models. Whichever model a lab picks, divisions and lineages will still need to be annotated by hand.

Errors gather where cells are crowded, except for LAP

In View 3 the orange and dashed links cluster in dense groups of cells, while isolated cells are tracked correctly. To check that this holds beyond one window, we measured how close each cell is to its nearest neighbour in the same frame, across all 12 sequences. Trackastra's and LineageMapper's error rates rise three- to fourfold from isolated to crowded cells, while LAP's stays between 5% and 8%. (Computed from the link files with prep/crowding.py.) This is the most practical result for a new experiment: the denser the culture, the bigger LAP's advantage.

Same cells, different models

Switching the model in View 3 keeps the sequence and window, so two models can be compared link by link. On U87 · FLD_2, transitions 35–38, LAP gets 102 links right with 2 wrong and 7 missed. LineageMapper gets 79 right, with 11 wrong and 30 missed.

Errors happen almost everywhere, and spike at the end

The error timeline for U87 · FLD_2 · LineageMapper has errors in 286 of its 288 transitions, with a median of 9 per transition. The highest spikes all fall in the last 20 transitions (273–282). Clicking a spike opens it: transitions 273–276 have 13 wrong and 52 missed links against 49 correct.

A biologist can use this to judge whether a model's failures are spread out, or tied to a moment in the experiment when the culture becomes dense.

Recommendation. For a new experiment, choose LAP. Avoid Trackastra and LineageMapper for dense cultures and for cell lines like U87 and HEK293T. For any model, check cell divisions by hand.
